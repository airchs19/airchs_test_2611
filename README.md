동대문 도매 의류를 판매하는 **쇼핑몰**을 만들기 위한 첫 단계 저장소입니다.
이 저장소는 **동업자와 방향을 상의하기 위한 컨셉 문서 + 직접 눌러볼 수 있는 화면 프로토타입**이고,
앞으로 ChatGPT/Codex, Claude/Claude Code, GitHub Copilot 같은 다른 AI와 이어서 작업할 때
바로 참고할 수 있는 기준점 역할도 합니다.

> 저장소 이름 `airchs_test_2611`은 **테스트용** 이름입니다. 정식 오픈 시
> `dongdaemun-trend-mall` 같은 이름으로 옮기거나 새로 만들 예정입니다.
> 이 저장소는 공유용 **공개(public) 데모**이며, 실제 결제·배송·회원 기능은 아직 없습니다.

## 3. 프로토타입(`index.html`)에 구현된 것

**화면 구성 (위에서 아래로)**

1. **상단 공지 바** — "동대문 직송 · 오늘만 최대 45% 타임특가 / 오늘 자정 마감"
2. **헤더** — 로고(새벽시장), 검색창, 장바구니(수량 배지), 모바일 메뉴
3. **히어로** — `Week 47 · 동대문 도매 신상` / "이번 주 동대문 베스트 특가",
   타임딜 **자정까지 남은 시간 카운트다운**, `특가 둘러보기` `셋업 컬렉션` 버튼
4. **혜택 안내** — 동대문 직송(평균 1~2일 도착) · 오늘출발(평일 오후 2시 이전 주문) ·
   5만원 이상 무료배송(미만 시 3,000원) · 7일 교환·반품
5. **카테고리 탭** — 전체 / 아우터 / 니트·맨투맨 / 팬츠·데님 / 원피스·셋업
6. **상품 그리드** — 특가가·정가·할인율·평점·리뷰 수·품절 사이즈·BEST 배지
7. **상품 상세 모달** — 색상 선택, 사이즈 선택(품절 표시), 수량, 장바구니 담기, 스펙 표
8. **장바구니 드로어** — 상품별 수량 변경/삭제, 합계·배송비 계산, 주문하기
9. **주문서 모달(데모)** — 주문번호가 생성되는 시늉만 하고 실제 전송은 없음
10. **그 외** — 검색, 찜(하트), 토스트 알림, 모바일 하단 바

**상품 데이터 (12개)**

- 파일 안 `<script>`의 `CATS`(카테고리)와 `PRODUCTS` 배열에 하드코딩되어 있습니다.
- 상품 한 건의 필드:

```js
{
  id: 'dd01', name: '캐시미어 블렌드 오버핏 코트', brand: 'DDM ATELIER',
  cat: 'outer',          // 카테고리 id (outer/knit/pants/set)
  art: 'coat',           // SVG 일러스트 종류
  price: 79000,          // 특가
  list: 129000,          // 정가 (할인율은 자동 계산)
  rating: 4.8, reviews: 1284, stock: 12, best: true,
  tags: ['오늘출발', '동대문직송'],
  desc: '...',                                  // 상세 설명
  colors: [{ n: '차콜', h: '#3a3b3f' }, ...],   // 색상 이름 + 견본 색
  sizes:  [{ n: 'S', sold: false }, ...],       // sold: true = 품절
  spec:   [['소재', '울 70% · 캐시미어 30%'], ...]
}
```

- 가격대: 29,000원 ~ 89,000원 (정가 대비 30~45% 할인), 여성 캐주얼 중심 + 남녀공용 일부

**기술 스택**

- 순수 HTML/CSS/JS 한 파일 (프레임워크·빌드 도구·npm 없음)
- CSS 변수로 색·라운드·타이포 토큰 관리 (`:root` 블록)
- 반응형 (모바일 우선, PC 넓은 화면 대응)
- 실제 서버 통신 없음 → `fetch`, 결제, 저장(localStorage) 전부 미사용

## 4. 동업자와 상의할 핵심 포인트

### ① 타겟 고객

- 지금 프로토타입 기준: **20~30대 여성 캐주얼** (아우터·니트·데님·셋업)
- 상의할 것: 여성복만 갈지 / 남녀공용까지 넓힐지, 연령대를 10대 후반까지 내릴지,
  "가성비 특가" 고객 vs "동대문 신상 민감" 고객 중 누구를 먼저 잡을지

### ② 상품 소싱 방향

- 동대문 도매 상가(동대문종합시장·디자이너클럽·누존·청평화·APM 등) **직접 사입** vs
  도매 사입 앱(도매매·셀러허브 등) **온라인 사입** vs **위탁 판매**(재고 없이 발주)
- 첫 테스트에는 사입 없이 **위탁/소량 사입**으로 시작하는 쪽이 재고 부담이 적음
- 동대문 특성: 신상 회전이 빠름 → **매주 신상 몇 개만 특가로 올리는 방식**이 컨셉과 잘 맞음

### ③ "특가몰" 컨셉

- **자정 마감 타임딜** + **도매가에 가까운 가격** + **소량 재고(품절 표시)** 를 축으로 함
- 배송·교환 정책(프로토타입에 반영된 값, 실제 운영 전 재확인 필요)
  - 동대문 직송, 평균 1~2일 도착 / 평일 오후 2시 이전 주문 시 오늘 출발
  - 5만원 이상 무료배송, 미만 시 3,000원
  - 수령 후 7일 이내 교환·반품 접수
- 상의할 것: 매일 딜을 바꿀지(운영 부담 큼) / 주 2~3회만 열지, 할인율을 어디까지 보여줄지

### ④ 만들 방법: 아임웹/카페24 같은 빌더 vs 커스텀 개발

| 항목 | 아임웹 · 카페24 (빌더) | 커스텀 개발 (이 저장소 방향) |
| --- | --- | --- |
| 초기 비용·기간 | 낮음 / 며칠 | 높음 / 수 주~수 개월 |
| 결제·배송·주문관리 | 기본 제공 (PG 연동 내장) | 직접 구축 + PG 계약 |
| 디자인 자유도 | 템플릿 + 일부 코드 수정 | 완전 자유 |
| 유지보수 | 업체가 처리 | 직접 또는 외주 |
| 비용 구조 | 월 이용료 + PG 수수료 | 서버비 + PG 수수료 |
| 추천 시점 | **1차 테스트·실제 판매 시작** | 차별화 기능이 필요해진 뒤 |

- **추천 흐름(안):** 지금 프로토타입으로 컨셉을 확정 → 실제 판매는 **아임웹/카페24로 먼저 오픈**
  → 주문·재고·고객 반응이 쌓이면 커스텀으로 옮길 부분만 개발
- 상의할 것: 실제 판매를 언제 시작할지(1~2개월 안이면 빌더가 현실적), 예산, 사업자 등록·PG 계약 담당

### ⑤ 그 밖에 정해야 할 것

- 브랜드명·도메인 확정 ("새벽시장"은 임시 이름)
- 사업자 등록 / 통신판매업 신고 / 개인정보처리방침 (실판매 전 필수)
- CS·교환·반품 처리 방식과 책임 범위(누가 응대할지)

## 5. 다른 AI와 이어서 작업할 때 (ChatGPT/Codex · Claude/Claude Code · GitHub Copilot 등)

### 먼저 읽을 것

- 이 README의 **1~3번**이 컨셉과 현재 구현의 전부입니다. 코드는 `index.html` 한 파일뿐입니다.
- 수정 범위별 위치:

| 바꾸고 싶은 것 | 파일 안 위치 |
| --- | --- |
| 색·폰트·여백 등 전체 분위기 | `<style>` 최상단 `:root { --ink, --paper, --accent ... }` |
| 브랜드명·문구·히어로 카피 | `<body>` 상단 마크업 (헤더·히어로) |
| 상품 목록·가격·재고 | `<script>` 안 `CATS`, `PRODUCTS` 배열 |
| 상품 이미지 | 각 상품의 `art` 값 → SVG 생성 함수 (인라인 `<svg>`) |
| 카드·모달 동작 | 같은 `<script>` 안 렌더 함수·이벤트 핸들러 |

### 개선 방향 (우선순위 제안)

1. **상품 데이터 분리** — `products.json`으로 빼고 `fetch`로 렌더 → 가격·재고 수정에 코드 수정 불필요
2. **실제 상품 사진** — 인라인 SVG를 이미지 URL로 교체 (`art` → `image`), 썸네일/상세용 2장 구조로
3. **백엔드** — Next.js 또는 Node(Express) + Supabase/Firebase. 최소 API: 상품 목록/상세, 재고, 주문 생성
4. **결제** — 국내 PG(토스페이먼츠 / 포트원(아임포트) / 나이스페이) + 카카오페이·네이버페이
5. **회원·로그인** — 카카오 로그인 중심(국내 쇼핑몰 관행), 비회원 주문 허용 여부 결정
6. **주문·운영** — 장바구니 서버 저장, 주문 상태·송장, 관리자 페이지(상품 등록·재고·주문 처리)
7. **배포** — 정적 단계는 Vercel/Netlify, 이후 서버 포함 배포. 도메인 연결
8. **품질** — 모바일 성능(이미지 최적화), Open Graph 썸네일, 모달 포커스 트랩·키보드 접근성
9. **분석** — 유입·전환 측정(GA4 또는 대안) 붙이기

### 작업 규칙(권장)

- 한 번에 한 가지(예: "상품 데이터 분리"만) 바꾸고, 변경 이유를 커밋 메시지에 남기기
- 실제 개인정보·결제 정보는 테스트 단계에서 받지 않기
- 컨셉이 바뀌면 이 README의 **1~4번**을 먼저 갱신 (문서가 기준)
